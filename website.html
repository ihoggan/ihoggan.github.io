Before you start

What you'll end up with, and what it can't do

A real website at an address like jsmith.github.io, that anyone can visit on a phone or a computer, which you can change whenever you like. GitHub Pages hosts it for free.

It's the right tool for a personal site, a CV, a project write-up, a club or a hobby page. It isn't for everything:

  • No shop, no payments, no logins. GitHub's rules don't allow it to run an online business or handle passwords or card details.
  • Pages only, no server. It serves the files you give it. There's no database behind it, so a contact form needs an outside service.
  • It's all public. On a free account the files behind your site are public too, not just the pages.

All you need is an email address and a web browser. A computer is easier than a phone for this.

The one rule

Everything you put in is public, and GitHub keeps every old version. Deleting something later doesn't remove it from the history. Never put in a password, your home address, your phone number, or anything from your work.

Step 1

Make a GitHub account

Go to github.com/signup and follow the prompts: email, password, then a username.

Choose the username carefully, because it becomes your web address. Username jsmith gets jsmith.github.io. Something close to your real name looks better on a CV than a gaming handle.

GitHub will email you a code to confirm your address, and will ask you to turn on two-factor authentication, a code from an app on your phone as well as your password. Say yes. It's what stops someone else taking over your site.

Check

You're signed in, and your picture in the top-right corner shows your username when you click it.

Step 2

Make the repository that holds your site

A repository, or "repo", is just a folder on GitHub that keeps every version of its files. Your website will live in one, and its name is what makes GitHub publish it.

  1. Click the + at the top right, then New repository.
  2. In Repository name, type your username followed by .github.io, for example jsmith.github.io. All lower case, even if your username has capitals.
  3. Leave it set to Public. Free accounts can only publish from public repositories.
  4. Turn on the option to add a README (on some screens it's a switch called Add README, on others a tick box, Add a README file). It gives the repository a first file, which makes the next step simpler.
  5. Click Create repository.
Check

You're looking at a page titled yourname / yourname.github.io with one file in it, README.md. If the name has a typo, Settings at the top of the repository lets you rename it.

Switch on GitHub Pages

  
This tells GitHub to publish the repository as a website.

  2. In the list down the left, click Pages.

Check
Refresh the Pages settings page. Near the top it says "Your site is live at https://yourname.github.io/" with a Visit site button. Not there yet? Click the Actions tab: a job called pages build and deployment is either still running (yellow) or finished (green tick).

    
  






  
Step 5

  
Visit it, and fix what's wrong

  
Open https://yourname.github.io in a new tab, then on your phone. That's your website, live on the internet.

  
If it doesn't work

  
    
    
  • "404 There isn't a GitHub Pages site here." Almost always the repository name. It must be exactly your username, in lower case, plus .github.io. Also check the file is called index.html, not Index.html or index.html.txt.
    • 
    
  • You see the README instead of your page. index.html is missing or misspelled, so GitHub fell back to the README.
    • 
    
  • Your change doesn't show. Wait two minutes, then force a fresh copy: Ctrl + F5 on Windows, Ctrl + Shift + R on Linux, Cmd + Shift + R on a Mac. Your browser keeps old copies of pages.
    • 
    
  • A link to another page is broken. Web addresses care about capitals. On this site the HUSTLER page is Hustler.html, so a link to hustler.html goes nowhere.
    • 
  

  

    
Check
Your page opens at your address, on a computer and on a phone. Send the link to someone. It counts once somebody else has seen it.

    
  






  
Step 6

  
Change it, and add more pages

  
To edit a page: click the file in your repository, click the pencil icon, make your change, then Commit changes.... The site updates a minute or two later. Every old version is kept, under History, so you can always see what you changed.

  
To add a page: create another file the same way, for example walks.html. Copy your index.html as a starting point so the pages match, then link to it from the home page:


<a href="walks.html">My walks this year</a>

  
To add a photo: Add file → Upload files, drag the picture in, and commit. Give it a short, lower-case name with no spaces, like helvellyn.jpg, then show it with:


<img src="helvellyn.jpg" alt="The view from Helvellyn" width="600">

  
The alt text is read aloud to people who can't see the picture. Always fill it in. Shrink big phone photos before uploading: a 5 MB picture makes a page slow to open on mobile data.

  

    
Check
Your home page links to a second page, the link works, and the second page links back.

    
  






  
Going further

  
How I actually work on this site

  
The browser is fine for small changes. For anything bigger I keep a copy of the site on my own computer, preview it there, and send the changes up in one go. On Ubuntu that looks like this:


# one-time setup
sudo apt install git gh
gh auth login          # choose GitHub.com, then "Login with a web browser"
gh repo clone yourname/yourname.github.io
cd yourname.github.io

# preview on your own machine: open http://localhost:8000
python3 -m http.server 8000

# send your changes to GitHub
git add .
git commit -m "Add the walks page"
git push

  
One trap, because I fell into it: when gh auth login asks how to log in, pick "Login with a web browser". The other option, "Paste an authentication token", needs a token you'd have to create first. The full set-up, with a check after every command, is in my nix6 workflow guide.


  
Your own address

  
If you'd rather have jsmith.co.uk than jsmith.github.io, you can buy a domain name from any registrar, usually around £10 a year, and point it at GitHub. It's the one part of this that costs money, and it's optional. GitHub's guide to configuring a custom domain covers it. Tick Enforce HTTPS once it's set up.


  
The limits

  
A published site can be up to 1 GB, with a soft limit of 100 GB of visitors' downloads a month. For a personal site you won't come near either. The details are in GitHub's Pages limits.






  
Before you share it

  
A two-minute safety check

  
Remember the one rule: it's public, and it's permanent. Before you send your link around, open every file in the repository and look for:

  
    
    
  • Passwords, keys, or anything copied from a settings file.
    • 
    
  • Your home address, phone number or date of birth.
    • 
    
  • Anything about your employer, your colleagues or your work systems.
    • 
    
  • Photos of other people who haven't said yes, especially children.
    • 
  

  
If you find something, don't just delete it and carry on, because the old version is still in the history. The simplest fix for a brand-new site is to delete the repository (Settings, right at the bottom) and make it again without the problem.






  
That's it

  
What I'd want you to take away

  

    

      
The name does the work

      
Most failures are the repository name or the file name. Lower case, spelled exactly.

    

    

      
Check before moving on

      
Each step is small. Confirm it worked before starting the next, and a mistake is never more than one step back.

    

    

      
Public means public

      
The history keeps everything. Look before you commit, not after.

    

  

  
This site is built exactly this way: plain HTML, one shared stylesheet, no build step. You can read every file of it in its repository. Made one? Stuck on a step? Tell me. If a step here is wrong or unclear, that's my fault, and I'll fix it.
