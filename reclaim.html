Saved from the scrap pile

Two office PCs from 2015 were about to be scrapped. One of them now runs Ubuntu, a local AI model, and a cast of characters that remember me between conversations. No cloud, no subscription, no new hardware. This is how, including the day I measured the characters' memories and found almost every one of them was invented.

Part 1

Two PCs nobody wanted

They were sitting in the server room at work: two Dell OptiPlex 3040s, small office desktops from 2015 with 6th-generation Intel Core i5 processors and 16 GB of memory. They were going to be scrapped. I asked if I could have them.

There's nothing wrong with them. They're just old enough that Windows 11 won't officially run on their processor, and that's enough to finish off a lot of perfectly good machines. So I didn't try. I put Linux on one instead.

I call it nix6.

Part 2

Ubuntu: the easy part, for me

I installed Ubuntu 24.04 LTS from a USB stick. It's supported with security updates until 2029, so this machine has years of life in it. I'm an IT technician, so the install itself was routine. Then I locked it down before doing anything else: a firewall that blocks everything incoming by default, automatic security updates, fail2ban to stop repeated login attempts, and a set of kernel network hardening settings.

The install is routine for me, but it won't be for everyone. The two things that stop most people aren't Linux at all: knowing whether your machine is up to it, and getting it to start from the USB stick. Both are covered in Do it yourself below.

Part 3

Where it actually bit: getting set up to build things

I hadn't used Linux seriously in years; the last time was Red Hat, dual-booted with Windows XP, on an IBM laptop. Installing Ubuntu was fine. Setting it up for Python and GitHub work is where the real problems were, and every one of them was the kind a beginner can't diagnose:

  • git and the GitHub tool weren't installed on a fresh Ubuntu. Every guide assumes they are.
  • My first project landed on a branch called master, because I ran git init before telling git to use main. Order matters, and nothing warns you.
  • The GitHub login tool offers "Paste an authentication token" as one of two options. Pick it and it demands a token you'd have to go and create first. I picked it.
  • I tried to push before telling git where GitHub was, and got an error that doesn't say that.
  • I named my program chat, and Ubuntu already has a chat: an old modem dialler. Mine silently lost. Now I run which <name> before choosing any command name.

I wrote each one down with its fix, then turned the whole thing into a step-by-step guide with a check after every step, and two scripts that make a new project in one command: nix6-tools.

Lesson

Instructions for beginners have to spell out the answer to every question the computer asks. If there are two options and one is a trap, someone will pick the trap. It was me.

Part 4

A local AI, and why I wanted one

If the internet goes down, I still want a way to look something up, or just play something. A model that runs on my own machine doesn't need anyone's servers, account or permission.

I used Ollama, which makes running a model one command, with Llama 3.2 3B, a small model that fits comfortably in this machine's memory. There's no graphics card. It all runs on the 2015 processor.

Roughly reading pace. Slow enough to notice, fast enough to hold a conversation.

A 3-billion-parameter model is not ChatGPT. It gets facts wrong, and it will confidently make things up. But it's very good at one thing I didn't expect: being someone. Give it a character and it stays in it. The trick I learned is that a reference beats a description. "Think of a particular comedian doing tech support" gets a far better voice than a list of adjectives like "funny, warm, Scottish".

Part 5

Characters that remember you

Out of the box, a local model forgets everything the moment you close it: your name, yesterday's conversation, and who it was supposed to be. So I built localcast, a small Python program that gives each character a folder with four parts. I call the set its personality matrix:

  • Persona: who they are, in plain English.
  • Diary: facts you've told them, carried into every conversation.
  • History: the last few turns, so they can pick up where you left off.
  • Config: which model, how spontaneous, how much history.

The main character is Dave, a grumpy Northern electrician who has no idea he's a computer program. The diary is filled automatically: when you leave, the model reads the conversation and proposes what Dave should remember, and you approve it.

It seemed to work. Dave would bring up things from earlier conversations, and I was pleased with it for about two days.

Part 6

The day I read Dave's diary

I'd mentioned, once, as a joke, that my van is a 1979 Transit and an embarrassment. When I finally read what Dave had "learned" about me, it said my company has a policy of replacing vans every five years, that management was worried older vans look bad, and that they were phasing them out. None of that was ever said by anyone. Dave's own made-up dog was in there too. So was "a new electrician". Not one line was a true fact about me.

Worse, it was feeding itself. The diary goes into every conversation, so Dave started bringing up the five-year van rule unprompted, which made it look like the truth.

Before changing anything, I measured it. Five scripted conversations with known facts, each run three times through the diary step, graded blind: the before and after results were shuffled together with their labels hidden, so the grading couldn't favour the fix.

Before the fix, the diary told Dave that "the M56 is a major motorway in the UK" three times, and not one true thing about me. Full method and raw data in the localcast repo.

The cause was simple once I looked. The step that wrote the diary couldn't tell who had said what, and it was asked for facts about "the Maker or the world". Everything Dave invented counted as "the world". And the approval screen defaulted to keep: pressing Enter accepted the lot. I can't honestly tell you whether I read those lines before pressing it.

The fix doesn't rely on the model behaving itself:

  • The diary step only looks at what I said. Dave's lines are marked as fiction.
  • Every proposed fact must quote my exact words, and the program checks that the quote really appears in something I said. If it doesn't, the fact is thrown away and I'm told why.
  • The approval screen has no default. Nothing gets in unless I type keep.
Lesson

An approval step you can pass without reading isn't one. And "the model will be careful" is not a safeguard. A check in code that can say no is.

The first real conversation after the fix, from an empty diary:

Maker: Hows it going Dave, long time no see?
dave:  What's up, Maker? Just had a busy day, been up to me elbows in

Updating diary…
Nothing new worth remembering.

Dave invented a job in Prenton, his own van, a hotel and a dog. None of it went into his diary. He also missed something true, the Transit, because the fix makes him err towards remembering nothing. That's the right way round to be wrong: a character who forgets is annoying, but a character who "remembers" things you never said is worse.

Part 7

What it can't do

  • Characters invent their own lives. That's usually what you want from a character, and it's why the diary only accepts your words.
  • They play along with a false premise. Ask Dave how the Wrexham job went and he'll describe a job that never happened.
  • The diary misses things. It caught about half the real facts in testing. For anything important, I tell him directly with /remember.
  • It can't tell real life from role-play. If I tell Dave I'm his boss, that's something I said.

Part 8

Do it yourself

If you have an old PC that Windows 11 won't take, this is the short version. The detailed guides are linked at each step.

Before anything else

Installing Ubuntu the simple way erases the whole disk, including Windows and everything on it. Copy off anything you want to keep first.

1. Check the machine is up to it

On Windows, press Windows key + R, type msinfo32 and press Enter. Look for:

  • System Type: it should say x64-based PC (64-bit).
  • Installed Physical Memory (RAM): 8 GB will run a small model. 16 GB is comfortable.
  • Processor: roughly 2012 or newer. Mine is a 2015 Core i5.

You'll want a disk of at least 25 GB for Ubuntu and the model; more gives you room to work.

2. Make a USB installer

You need a USB stick of 8 GB or more (it will be wiped). Download Ubuntu 24.04 LTS Desktop from ubuntu.com and follow Ubuntu's own guide to making the USB stick on Windows.

3. Start the PC from the USB stick

This is where people get stuck. With the stick plugged in, turn the PC on and immediately tap the boot menu key repeatedly. On Dell machines like mine it's F12. On others it's often F11, F10, F9 or Esc, and the right key usually flashes on screen for a second at power-on. Choose the USB stick from the list.

If it boots straight into Windows, you missed the moment. Restart and tap sooner. You normally don't need to change any BIOS settings: Ubuntu works with Secure Boot left on.

4. Install Ubuntu

Choose Install Ubuntu, then Erase disk and install Ubuntu, and follow the prompts. About twenty minutes.

5. Set it up for building things

Part 1 of my nix6 workflow guide: every command, every prompt's answer, and a check after each step.

6. Add the AI and the characters

curl -fsSL https://ollama.com/install.sh | sh
ollama pull llama3.2:3b
ollama run llama3.2:3b

That's a working local AI. Type to it; /bye leaves. For characters that remember you, follow the install steps in the localcast README.

What came out of it

A second life, and a method

A machine that was going to be scrapped is now the most interesting computer in the house. The same working method that built HUSTLER carried straight over: measure before you change anything, report numbers rather than adjectives, and don't trust a safeguard until you've watched it say no.

Old isn't obsolete

A 2015 office PC runs a modern Linux, a local AI model at reading pace, and everything I build.

Read what it remembers

Automatic memory from a small model will invent things. Make it quote you, and check the quote in code.

Spell out every answer

Beginners don't fail on the hard parts. They fail on the prompt with two options where one is a trap.

Found a mistake, or tried this on your own old PC? Tell me. Corrections are genuinely welcome.
