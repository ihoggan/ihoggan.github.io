Make your website work with no signal

This site installs on a phone like an app, and every guide still opens in flight mode, in a power cut, or halfway up a hill with no signal. It took four small files, and none of them need a server, an account or any money. This tutorial builds the same thing for your own site, one file at a time, with a test after each step. The idea

A helper that lives in the browser

Normally, every time you open a page, the browser asks the website for it. No signal, no page. A service worker is a small script your site gives the browser, which then sits between the browser and the internet. On a visitor's first visit, it saves a copy of your pages on their device. Later, if the network isn't there, it hands over the saved copy instead.

The four files:

manifest.webmanifestThe name and icon, so the site can be installed on a home screen.
register.jsThree lines that switch the service worker on.
sw.jsThe service worker: what to save, and what to hand over when there's no signal.
offline.htmlA friendly page for when someone asks for a page that was never saved.
Two things it needs

Service workers only run on https sites, plus localhost for testing on your own computer. GitHub Pages is https, so you're covered. They also don't run on pages opened straight from a file on your disk.

Step 1

The manifest: a name and an icon

Create manifest.webmanifest in the same folder as your index.html:

{
  "name": "My Guides",
  "short_name": "Guides",
  "start_url": "./index.html",
  "scope": "./",
  "display": "standalone",
  "background_color": "#ffffff",
  "theme_color": "#222222",
  "icons": [
    { "src": "icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "icon-512.png", "sizes": "512x512", "type": "image/png" }
  ]
}

You'll need two square PNG icons, 192 and 512 pixels wide. Any simple image works: a letter on a coloured background is fine. Then add these lines inside the <head> of every page:

<link rel="manifest" href="manifest.webmanifest">
<meta name="theme-color" content="#222222">
<script src="register.js" defer></script>

start_url is the page that opens from the home-screen icon. display: standalone hides the browser's address bar, so it feels like an app.

Step 2

Switch it on

Create register.js. The if means browsers that can't do this simply skip it, so nothing breaks:

// register.js: switch on offline support, if this browser can do it.
if ('serviceWorker' in navigator) {
  window.addEventListener('load', () => {
    navigator.serviceWorker.register('sw.js');
  });
}

Step 3

The service worker

Create sw.js, and put your own pages and stylesheet in the FILES list:

// sw.js: keeps a copy of the site on the visitor's device.
const VERSION = 'v1';                       // change this whenever you change a file
const FILES = ['./', 'index.html', 'about.html', 'style.css', 'offline.html'];

// 1. Install: save every file in the list.
self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open(VERSION).then((cache) => cache.addAll(FILES)).then(() => self.skipWaiting())
  );
});

// 2. Activate: delete copies saved by older versions.
self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys()
      .then((names) => Promise.all(names.filter((n) => n !== VERSION).map((n) => caches.delete(n))))
      .then(() => self.clients.claim())
  );
});

// 3. Fetch: pages try the network first; everything else uses the saved copy first.
self.addEventListener('fetch', (event) => {
  const request = event.request;
  if (request.method !== 'GET' || new URL(request.url).origin !== location.origin) return;

  if (request.mode === 'navigate') {
    event.respondWith(
      fetch(request)
        .then((response) => {
          const copy = response.clone();
          caches.open(VERSION).then((cache) => cache.put(request, copy));
          return response;
        })
        .catch(() => caches.match(request, { ignoreSearch: true })
          .then((saved) => saved || caches.match('offline.html')))
    );
  } else {
    event.respondWith(caches.match(request).then((saved) => saved || fetch(request)));
  }
});
What each part does

Install runs once, on a visitor's first visit: it opens a storage box named after VERSION and saves every file in the list. Activate clears out boxes from older versions, so old copies don't pile up. Fetch runs for every request. For pages, it tries the internet first, so visitors with signal always get your latest words, and it keeps the fresh copy. With no signal, it hands over the saved copy, or offline.html if there isn't one. For everything else (stylesheets, images), it uses the saved copy straight away, which is also why the site gets faster.

The first line of the fetch part matters for safety: it only touches simple requests (GET) for your own site. Anything else, such as forms or other websites, goes straight to the internet untouched.

Step 4

A page for "not saved yet"

Create offline.html as an ordinary page from your site, with a short message like "You're offline, and this page hasn't been saved on this device yet. The pages you've already opened will still work." Make sure it's in the FILES list, because it has to be saved before it's needed.

Step 5

Test it, then cut the signal

Push your changes, wait a minute for GitHub Pages, then open your site in Chrome, Edge or Firefox on a computer:

  1. Press F12 to open developer tools, then find the Application tab (Firefox calls it Storage).
  2. Under Service workers, you should see sw.js marked as activated and running.
  3. Under Cache storage, open v1: every file in your list should be there.
  4. Back under Service workers, tick Offline, and reload the page.
Predict first

With "Offline" ticked: what happens when you reload a page you've visited? And when you type the address of a page that isn't in your list, and you've never opened?

What should happen

The visited page reloads normally, styles and all: it came from the saved copy. The unvisited page shows your offline.html. I tested exactly this before writing it up. If you see the browser's own "no internet" page instead, the service worker isn't running yet: reload once with the signal on and try again.

Then the real test, on a phone: open the site, use the browser's Add to Home Screen (or Install) option, switch on flight mode, and open it from the new icon.

Check

Your site opens from its home-screen icon in flight mode, and an unsaved page shows your offline page rather than an error.

Step 6

The catch: keeping copies fresh

Predict first

You change the colours in style.css and push it. A visitor who came last week comes back. Which colours do they see?

The answer

The old ones. Stylesheets come from the saved copy first, and nothing told the browser that copy was out of date. The fix is the VERSION line: change v1 to v2 whenever you change any file. The browser notices sw.js has changed, installs the new version, saves fresh copies, and the activate step throws the old box away.

Lesson

Every change to the site means a change to VERSION. Forget it, and your visitors are stuck in the past without knowing it.

Remembering that by hand gets old fast. This site has a small script, tools/build_offline.py, that I run after adding a page: it rebuilds the list of files to save, and sets VERSION from a fingerprint of all of them, so it only changes when something actually did. It's in the site's repository if you'd like to borrow the idea.

What it doesn't do

Honest limits

  • Only what's been saved. Pages in the list, plus any page a visitor has opened. Nothing else is there in flight mode.
  • Not other websites. Fonts or scripts from elsewhere won't be there offline unless you save them on purpose. This site saves its fonts; the live Python on the Data path needs the internet.
  • Storage can be cleared. Browsers may clear saved sites that haven't been used for a long time, or when the device runs short of space.
  • No tracking. A service worker can't see other sites, and this one sends nothing anywhere. It only saves and hands back your own pages.

What I'd want you to take away

Four small files

A manifest, a register script, a service worker and an offline page. No server, no cost.

Network first for pages

Fresh words when there's signal, the saved copy when there isn't.

Bump the version

Change any file, change VERSION, or visitors keep the old copy.
